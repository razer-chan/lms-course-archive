# 现场经验：哪些判断容易出错

这些经验来自 2026-11-13 的一次 SCU Blackboard + Zoom 实际归档。当时两门课最终共 52 场，38 场取得官方字幕（33 个 VTT、5 个官方面板 TXT），14 场保存原始音频，没有新转录。它证明这条流程曾奏效，不保证其他学校、浏览器或后续版本有相同结构。

接手 AI 可以选择自己的实现。下面保留现象、原因线索和有效检查，不要求照抄按钮名称或旧接口。

| 当时观察到的现象 | 有效处理与经验 |
|---|---|
| 从旧的 Zoom 子页面地址直接进入时课程状态不稳定 | 从 LMS 课程的 Zoom/LTI 入口重新进入，让平台建立当前课程上下文 |
| 进入页面时暂时显示没有 recordings | 等列表真实加载完，再判断是否为空；检查筛选和分页 |
| 页码已经变化但行还是上一页 | 用行的录播身份确认翻页完成，而不只看页码 |
| 同时打开第二门课后，第一门课的搜索/分页报错或显示旧内容 | 回到第一门课 LMS 入口重新进入；按课程串行处理消除了本次问题 |
| 详情最初只有不明 `play`、视频和 Audio only 卡片 | 点开相关卡片后页面刷新，才出现字幕或密码按钮；初始卡片不代表全部资源 |
| 没有 Audio transcript 卡片，但播放器能看到字幕 | 继续检查已授权播放器；字幕卡缺失不等于官方字幕不存在 |
| Copy Passcode 显示成功但工具读取剪贴板为空 | 改用对应卡片的 Display Passcode，填进匹配资源的密码表单；不公开记录密码 |
| 下载了后缀为 `.vtt` 的几百 KB 文件 | 实际内容是 HTML；检查签名和 cue 后才算字幕成功 |
| 官方面板的可访问性树包含所有 cue | 导出官方 TXT，保留说话人和真实开始时间；只有起始时间就不生成伪造结束时间的 SRT |
| 另一版面板采用虚拟滚动 | 页面快照只有屏幕附近字幕；改读播放器实际取得的完整 VTT 响应，或做有覆盖证明的滚动抓取 |
| 短录播的 cue 标签没有“小时”字段 | 时间解析兼容分钟/秒及小时格式，不按单个样例硬切字符串 |
| 密码跳转前开启 Network，之后没有事件 | 等播放器加载后重新观察，再普通刷新，获得新的响应 ID |
| `getResponseBody` 对旧 ID 返回无数据 | 重新捕获当前请求；旧响应 ID 不是可长期复用的下载地址 |
| 某媒体下载工具长时间挂起，导航到 CDN 后失败 | 检查浏览器下载/原生保存窗口，或读取播放器已获授权的完整响应；不能把失败当文件存在 |
| 音频响应是 HTTP 206 | 本次 14 条短音频实际范围覆盖整个文件，核对 range 和长度后解码成功；其他录音的 206 可能只是一段 |
| 官方 VTT 只有一个短 cue | 可能就是官方提供的全部字幕，不按“太短”直接丢弃；核对来源和响应完整性 |
| 字幕比视频早结束约 18–30 分钟 | 部分场次观察到课程结束后反思留屏，其他差值原因未确认。保留完整官方字幕并报告差值；不据此直接推断静音或缺稿，也不生成新转录 |
| 结束时重新盘点比开始时多一场 | 将新增场次加入 inventory 并处理；保留原来的稳定身份和文件路径，不以旧总数宣告完成 |

## 真实性与完成判断

“官方字幕”描述来源，不保证平台识别正确。归档保留平台原文；不要悄悄纠错、润色或翻译。

“完整响应”证明拿到了该响应全部字节；还需要确认它属于目标录播、正确片段/语言，以及录播是否另有其他片段。相反，字幕尾部与录播总时长不一致，本身不能证明抓取不完整。

“没有字幕”与“有字幕但当前工具取不全”应分开记录。后者保留音频也不能算已完成字幕目标。

清单中的完成状态应由当前网页检查、文件验证和最终目录对账共同支持。清单脚本不能替 AI 判断网站是否漏页，也不能因没有错误日志就把任务称为完成。
