# 浏览器与工具适配

这是能力映射，不要求接手 AI 使用原作者的工具名称。宿主工具的限制和当前 API 文档优先于下面的历史示例。

## 初次使用时怎样引导用户

1. 读取用户给出的课程链接和浏览器偏好；缺哪项再问哪项。
2. 检查宿主现有浏览器/连接器，确定它能访问的具体浏览器或会话。不要直接假设它能接管用户桌面上的任意浏览器。
3. 先检查该会话能否显示目标课程；可访问就继续。未登录或会话失效时，才请用户登录学校 LMS，完成可能出现的学校 SSO、MFA 或验证码，再检查课程标题及内容。
4. 从课程内的 Zoom 入口打开 Cloud Recordings；只要用户已授权此课程归档，就继续盘点和下载，不逐场询问确认。
5. 如果没有浏览器控制能力，具体说明需要宿主的浏览器工具/扩展，或者改用用户手动下载官方字幕和音频、AI 负责本地整理。Skill 文件自身不能安装浏览器控制权限。

不需要索取账号密码或导出整个浏览器配置文件。不要把用户个人会话复制进交付包。正常登录是入口，录播 passcode 是对应资源的另一层访问表单。

## 能力与可替代方式

| 所需能力 | 可用实现举例 | 适配要点 |
|---|---|---|
| 已登录课程访问 | 宿主浏览器连接器、Computer Use、受支持的已认证浏览器自动化 | 实测目标课程可打开；另一会话的登录不会自动继承 |
| 读取分页与详情 | DOM/可访问性树、截图加界面操作 | 等待实际行变更；不要只看页码控件 |
| 官方字幕保存 | 下载按钮、官方导出、受支持的网络响应正文读取 | 查验原件，不把 HTML 或虚拟滚动中的部分字幕当完整文件 |
| 官方面板全文导出 | 完整 DOM、可证明覆盖的滚动采集 | 记录 cue 来源及覆盖证据；只保留真实时间戳 |
| 原始音频保存 | 正常浏览器下载、受支持的媒体下载、完整响应正文 | 保留原始字节；检查 Content-Length / Content-Range 和格式 |
| 文件落盘 | 工具下载产物、宿主文件工具、允许的本地脚本 | 以本地实际文件和哈希为准，不以下载提示为准 |
| 本地归档与清单 | 随包 Python 脚本，或接手 AI 自己实现 | 清单需逐场对账，保留状态、来源、验证等级 |

没有网络/CDP 工具不等于无法完成，正常下载往往就够用。如果确实依赖响应读取才能取得全文，而宿主没有该能力，则明确说明受阻原因，提供用户可执行的正常下载步骤，不绕过工具限制。

## 一条曾成功的网络响应路线

以下是在已登录且输入正确资源密码后的播放器中，**读取播放器自己取得的内容**的经验，不是固定接口规范。

1. 通过宿主支持的工具开启当前标签页的网络观察，记录游标或清空本次事件范围。
2. 普通刷新已授权播放器，等待字幕/音频加载。
3. 从新响应中找到实际字幕资源。曾观察到 `mimeType = text/vtt`，路径包含 `/rec/play/vtt`；这些只是识别线索，不能据此自行拼接 URL。
4. 如工具支持 CDP，可从 `Network.responseReceived` 得到 request ID，等待工具确认响应正文可用后，再用 `Network.getResponseBody` 读取正文。按返回的编码标志处理，字幕响应也可能需要 base64 解码。以当前工具文档为准；不支持 CDP 的工具使用自己的等价能力。
5. 校验正文以 WEBVTT 开始、含可解析 cue，并与当前录播对应。去重相同响应；不同语言或片段保留对应关系。
6. 若网络观察是在密码跳转前启用而未收到事件，可在播放器已加载后重新观察、重新取游标并普通刷新一次。旧 request ID 可能过期，失败后要重新观察，而不是循环使用旧值。

音频响应有时是 base64。有完整响应时可以直接解码保存，不需要播放录音或识别语音。对于 `Content-Range: bytes 0-(N-1)/N`，还需核对解码后确有 N 字节。`bytes 0-999/N` 且 N 大于 1000 只是第一段。若拿到的是多个范围，应走正常完整下载或可验证的合法范围重组；随包脚本不会假装一个分块就是整条录音。

不要保存完整网络日志：里面可能有 Cookie、令牌、签名 URL。仅保留内容正文和去敏后的来源及校验元数据。

## 文件传递与系统差异

优先使用工具原生的下载文件/产物导出。若浏览器运行在隔离环境里，确认产物实际复制到了用户可访问的本地目录。

曾在一个无法直接写文件的 macOS CUA 环境中，用受控文本编辑器缓冲区保存字幕文本或小型音频响应的 JSON/base64，再交给本地 Python 校验写入。这只是该环境的传递办法，不依赖 TextEdit 的算法，也不应成为 Windows/Linux 用户的前置条件。大文件优先使用原生下载，避免把整段二进制输出到聊天。

浏览器下载可能触发原生“另存为”窗口；出现等待时检查窗口与下载状态。使用工具允许的有界等待和重试，处理超时后重新查看当前页面；不要把长期挂起的下载调用当作工作仍有进展。

## 依赖范围

- 必需能力：访问用户授权的课程、浏览器页面操作/读取、文件保存。
- 可选能力：读取当前播放器网络响应，截图或原生窗口控制。
- 随包脚本：Python 3.10+，仅标准库，没有 pip 依赖；可以不用这些脚本而实现同样的归档合同。
- 可选程序：`ffprobe`，只检查媒体容器、流和时长；没有它仍可保存文件，但报告核验不足。
- 不需要：Zoom 管理员 API key、学校管理员权限、特定收费连接器、转录服务、Whisper/MacWhisper、GPU 或模型文件。
