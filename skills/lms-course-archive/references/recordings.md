# LMS / Zoom 录播归档

把用户指定课程中可访问的全部 Cloud Recordings 保存到本地，按课程、场次清楚分类，并交付逐场清单。

默认每个录播片段优先保存**官方字幕原件及可读 TXT**；确认没有官方字幕时保存**原始音频**。如果用户明确还要有字幕场次的音频，也一起保存。这里的官方字幕指平台发布的字幕，可能本来就是平台自动生成的；本录播模块 不生成任何新转录。不运行本地或云端 ASR，不安装转录模型，不把摘要当逐字稿。本节只处理录播；课件、论坛、作业等由主流程的材料模块处理。

本录播模块 提供方法、经过验证的经验和可选本地脚本，不是绑定某个学校接口的下载器。页面结构、接口和工具可能变化：先观察当前环境，选择宿主允许且能达到相同目的的方法。不要照抄历史选择器、猜测下载接口，或假设安装 skill 就自动获得浏览器权限。

## 1. 接手与登录

先复用对话里已有信息，只补问缺失的课程链接、用户希望使用的浏览器，以及有必要确认的保存位置。默认范围就是上述“官方字幕优先、无字幕存音频”，不反复确认已确定的需求。

检查当前 AI 能使用的浏览器、网页连接器和文件工具，阅读它们的现行说明。需要能访问用户授权的课程会话、读取页面/切换分页，以及将下载内容保存到本地。支持网络响应正文的工具能帮助取得完整字幕，但不是必需条件。具体适配见 [浏览器与工具适配](recording-browser.md)。

先检查选定会话能否打开目标课程；已经登录且内容可访问就继续，只有未登录或会话失效时才引导用户登录学校 LMS。登录、MFA、验证码由用户按宿主要求完成。用户说“已经登录”不代表另一浏览器或连接器共享该会话。缺少工具或访问权限时，指出缺的是哪项能力及用户可执行的下一步，不把未访问的课程当成没有录播。不要求用户在聊天中提交账号密码、Cookie 或完整认证令牌。

## 2. 从课程建立完整目录

从目标课程的 Zoom / 在线课堂入口进入 Cloud Recordings，让 LMS 建立正确的课程上下文。曾见入口是 `Classes → Join a class (Zoom)`，当前名称可能不同。

检查当前筛选条件、日期范围、分页和折叠分组，收集全部可见录播场次。每场记录课程、标题、列表显示时间、会议/录制标识、来源页面；同时保留页面显示的时区。不要自行把无时区时间改称用户本地时间。

使用稳定的录制 ID；没有时可结合课程、会议 ID、完整开场时间及片段身份。重复会议的 meeting ID、同名标题、分页行号单独使用都不能保证唯一。建立 inventory 后逐场处理，保留 pending / blocked / failed 等状态。

页面可能先显示空列表、旧页内容或未加载完的卡片。确认实际行内容已更新再计数。若同时打开不同课程后出现串课或分页异常，逐门课程处理，并从对应 LMS 入口重新进入。经验细节见 [现场经验与故障处理](recording-field-notes.md)。

## 3. 逐场取得官方字幕或原始音频

打开详情，检查所有片段、音轨和字幕语言。部分资源需要先点击播放卡片，页面才刷新出字幕卡或 passcode。记录各片段的覆盖情况，不能用第一段文件代表整场。

有密码时，使用该场该资源在已授权 LMS 中显示的 passcode，通过播放器的正常密码表单进入；复制按钮无效时可使用页面的显示密码功能。不要猜密码或跨录播复用密码。密码只用于当前访问，不放入文件名、清单或交付包。

按当前可用能力选择路线，无须机械执行每条：

- **官方字幕下载**：优先保存原始 VTT / SRT / TXT，校验内容后再生成可读 TXT。下载成功提示或 `.vtt` 文件名不证明文件正确，实际内容可能是 HTML 登录页。
- **播放器请求的完整字幕**：若播放器可显示完整字幕，但没有可用下载入口，可用宿主允许的浏览器网络工具，读取当前授权页面实际请求的官方字幕响应正文。以实际观察到的请求或当前可用的已授权 API 为依据，不仅凭历史路径猜测请求，也不绕过工具限制。完整 VTT 响应优于只读屏幕可见部分。
- **完整官方字幕面板**：若工具只能读页面，确认是否虚拟滚动。只有能证明全部 cue 已取得，才可导出官方 TXT；可以完整滚动、稳定键去重并核对首尾及数量。只有开始时间时保留开始时间，不能捏造结束时间来伪装 SRT/VTT。无法证明完整时记录受阻，不能把可见窗口称为全文。
- **没有官方字幕**：详情卡片和已加载播放器均检查后，保存原始音频。优先使用正常下载；也可使用宿主支持的、来自实际授权播放请求的音频响应。部分 HTTP 206 只是片段，需核对完整字节范围和长度。无法拿全时记录未完成，不进行转录来补救。

找到了字幕但暂时拿不到完整内容，应注明“字幕存在但抓取受阻”。可先保留音频作为临时备份，但不能写成“没有字幕”或把该项算作字幕完成。

## 4. 本地整理与核验

按课程、日期、稳定场次标识建目录；一场多个片段分别保存。保留官方原件，另生成 TXT，保留原文、说话人、cue 顺序和来源提供的时间戳。不要润色、翻译或纠正官方识别错误。

已有文件核对内容哈希后复用；内容不同保留版本或报冲突，不覆盖。保存非敏感来源、捕获方式、文件大小、SHA-256、字幕条目数、首尾时间，以及音频校验结果。不要把浏览器会话、密码、签名下载 URL 或个人录播打进 skill 本身。

可使用随包的 Python 标准库工具，也可用自己的等价实现。工具不联网、不操作浏览器、不转录；只整理已经合法取得的本地文件。用法与清单格式见 [本地整理工具](recording-files.md)。运行前先看 `python3 scripts/recording_archive.py --help`。Python 3.10+ 仅为使用这些脚本所需；`ffprobe` 可选，用于音频格式/时长核验，缺少时如实降低校验等级。

区分两种“完整”：字节/文件完整，以及该场所有所需片段已覆盖。短字幕也可能是完整官方文件；字幕末尾早于播放器结束可能因为静音、反思或留屏。记录时间差，结合源响应/面板检查，不自动补写或转录。脚本的文件校验不能代替网页端盘点。

## 5. 对账与交付

结束前再次核对全部列表页，处理运行中新出现的场次。每个 inventory 项都要落到有文件的成功记录或明确的未完成原因；未完成项不可从分母删除。

交付本地目录和人类可读清单，包含课程、标题、显示日期、各片段字幕/TXT/音频路径、获取方式、验证等级及异常。另附 JSON / CSV 便于以后合并课程资料。汇报总场次、官方字幕场次、音频回退场次和未完成项；一场多资产时说明计数口径。

只在网页目录已对账、所有必需片段有合格文件、且没有 pending / blocked / failed 时声明全部完成；没有 ffprobe 或无法独立证明的内容，明确说明核验范围。
