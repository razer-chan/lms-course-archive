# 开发与适配

本包把完整流程放在一个 skill 目录中，安装时不依赖旁边另一个 skill。主文件只编排工作，具体材料和录播经验按需读取。浏览器由宿主提供，随包脚本不内置学校账号或固定抓取接口。

## 本地工具边界

| 文件 | 职责 |
|---|---|
| recording_archive.py | 校验已经取得的官方字幕/原音频，保留原件，生成 TXT 和逐场清单 |
| build_course_index.py | 对照明确 inventory 汇总材料与录播，并重新检查文件哈希 |
| capture_receiver.py | 仅在显式启动后接收允许来源送来的数据，保存到指定本机目录 |
| browser_capture.js | 显式配置后访问已观察且授权的同源 GET 资源；不自动找课程或开启任务 |

前三个脚本只需 Python 3.10+ 标准库。运行 JavaScript mock 测试需要 Node；浏览器使用脚本本身不需要安装 Node。ffprobe 为录播音频验证的可选工具。

## 运行测试

在仓库根目录运行：

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
node --check skills/lms-course-archive/scripts/browser_capture.js
node tests/test_browser_capture.js
```

测试使用合成材料、临时目录和本机 HTTP；不会登录真实学校，也不会把数据送到外部服务。测试范围包括分页不完整、字幕/音频范围、幂等、文件冲突、路径检查、总清单对账及缺项状态。

## 适配新学校或工具

先通过 UI 确认用户有权访问的课程与资源，再观察当前结构，测试一个页面、一个附件和一个录播。复用已有格式处理与清单，替换浏览器采集办法即可。历史路径、iframe 名称、字幕面板实现与日期显示规则都不应成为跨学校断言。

已登录页面 GET、网络响应导出、正常文件下载、完整 DOM 捕获均可选；哪个方法被宿主支持，就采用哪个。不把任何一个私有工具名称或系统程序当作所有客户端都有的能力。

## 此次合并的取舍

保留非录播流程的广泛覆盖：内容树、嵌入附件、公告、完整论坛树、rubric、阅读清单和媒体链接；结合旧归档的来源与完整性约束，以及新录播模块的官方字幕优先/无字幕原音频策略。

没有沿用这些过时或不可靠的判断：父节点 body 空就没有正文、API 列出就证明学生可见、questionCount=0 就证明没有题目、分页到上限仍算成功、仅凭文件存在就跳过、所有 LTI 都不能打开、录播有密码一律跳过、没有字幕必须 ASR、转换后删除 VTT。

材料与录播分别维护可续跑的清单，总索引再关联两者。这样其中一类结构变化时，可以只适配那部分，也能保留此前已经取得的文件。
